# Model configuration and security

## Administrator-owned configuration

Authenticated settings maintain versioned model lists, policy rules/prompt and stage weights. Saves use optimistic version checks. Blank API Key retains the previous encrypted secret; deleting a model removes it from future configuration, not existing short-lived job snapshots. Each submitted job snapshots its configuration so later edits cannot silently change the running policy/model/weights.

Assign enabled models to `research`, `team`, `synthesis` roles. Model IDs are operator supplied, not assumed universal. Only OpenAI-compatible is supported; its base URL is an administrator-controlled HTTPS text endpoint, not a user-selectable proxy. A malicious admin endpoint can exfiltrate inputs: administrators are trusted operators, not sandboxed tenants.

Keys use AES-256-GCM with fresh IV/authentication tag and a 32-byte deployment secret. Masked reads, session-only authentication, same-origin CSRF checks and strict submission schemas prevent ordinary form requests from selecting keys, endpoints or system prompts. Browser state and JS bundle contain no model secret. Model calls, including admin connectivity checks, are backend-only; entering a key into admin necessarily sends that new value to your backend over TLS.

## OpenAI-compatible text analysis

`server/gateway` calls `/chat/completions` with `messages`, `max_tokens` and the configured model ID. The text gateway has no native xAI adapter or search tools; its own search flags remain false. Generated links are never accepted as evidence. The admin connection test checks the saved model's text response and returns usage; it does not certify research quality or the separate search service.

Optional `BRAVE_SEARCH_API_KEY` enables separate backend public discovery. Each new job encrypts this key into its immutable snapshot; old snapshots without the field leave search disabled. No database schema migration is needed. One Brave request queries only the submitted public hostname (or a Deck website's hostname after public identity confirmation), never Deck text, notes, private URL paths or query tokens. At most six results are inspected and four unique candidates fetched, with a 12-second API timeout, 512 KB decoded response limit and 60-second discovery deadline. The existing HTTPS/DNS-pinned/SSRF/robots reader retrieves each candidate before it can become evidence; snippets are not evidence. `searchUsed` indicates a completed discovery response, not independent verification or guaranteed additional evidence. `xSearchUsed` stays false. Missing keys, failed searches and inaccessible results are disclosed and do not discard usable website/PDF evidence.

Gateway failures are typed/sanitized. HTTP 429/502/503/504 can retry once; ambiguous timeout/network errors are not replayed automatically. Structured answers use the existing JSON parser and Zod contract; a completed but malformed answer can get one correction, within seven gateway invocations total. Starting from minute eight, new model calls stop and in-flight timeouts are capped to that analysis deadline, leaving time before the worker's ten-minute hard cutoff to save validated results. Each gateway invocation can still make the gateway's bounded HTTP retry. Raw provider usage and elapsed times are retained per module in `job_usage`, no private prompts. Provider-specific prices and a USD budget enforcement engine are not implemented; use provider spend limits. Execution summary shows provider/model/search flags/time; per-call usage is not a public user response.

## Confidentiality and untrusted material

PDF input is private. If any downstream role lacks `allowConfidential=true`, all Deck text is omitted from all model calls to avoid indirect cross-provider leakage. PDF-only research may use a website literally present in the permitted Deck only after securely retrieving its public origin and confirming the named company in public text; private paths/query tokens are removed before retrieval. Without public identity confirmation the page is not accepted as evidence. Notes remain unverified context; do not put secrets in them.

System prompts label website/PDF/social/tool text as untrusted. Only server rules choose policy and confidence thresholds, only code calculates weighted totals, and IDs must bind to a retrieved ledger. These structural controls do **not** guarantee a model will always classify sectors correctly or resist every semantic injection. Independent manual review remains necessary. Same-name third-party professional facts are rejected unless the name is in primary evidence and the cited source explicitly links name and company; conservative string matching can miss transliterations/aliases. Each team sub-score needs its own rationale and references to accepted professional facts. Concrete but incomplete company-attributed roles or experience may support a `partial` sub-score without external corroboration; the backend caps it at 2/5. Missing, insufficient or unbound support still makes that sub-score null. Generic praise without attributable professional facts cannot manufacture founders or scores.

Verified facts with only official/Deck evidence are downgraded to company claims. Each module is validated before assignment: unbound IDs or invalid comparables reject that module, not earlier validated identity, dimensions or team results. A clear company/product identity and any evidence-backed non-insufficient dimension permit analysis before numeric scores are available. Partial dimensions count toward scoring coverage but are capped at 2/5, including a team dimension with any scored partial sub-score. Unknown dimensions stay null. The overall score normalizes the scored weights, without requiring all three core dimensions; the default minimum coverage is 5%, including the boundary. Coverage measures scored dimension weight (including partial support), not independent verification or confidence. The final report mode is decided again after synthesis; almost-empty evidence still yields a factual brief without a total. Administrator thresholds and identity protections remain enforced. Synthesis cannot replace independent team scores, including when extraction omitted that dimension. Direct comparable categories require workflow/product/customer fit fields and evidence; financing unknowns remain null; undated public metrics are suppressed. An accessible source is not proof of every associated fact. Entailment, round compatibility and true economic comparability still require model judgment/manual review; no deterministic truth oracle is claimed.

## Input and temporary storage

Website reader: HTTPS-only, public DNS/IP checks, pinned socket lookup, safe redirects, robots, bounded 8-page/depth-2 crawl, time/byte limits. Transient DNS timeouts at submission do not reject the entire task; the reader repeats all address validation before making a connection. Unsafe resolved addresses still reject submission. Chinese product/team/about link labels and English solution/feature paths are recognized. Crawl deadline expiry retains pages already retrieved. No login, CAPTCHA bypass, unauthorized LinkedIn collection or JavaScript rendering. Robots failures may prevent evidence retrieval; limitations are not evidence of a weak company.

PDF: authenticated metadata init and streaming private PUT, MIME/extension/signature/size checks, 25 MiB and 40 pages maximum. Duplicate PUT cannot claim/delete another in-flight upload; upload IDs cannot be reused across jobs. Extraction runs in a child with sanitized environment, Node permissions and bounded time/heap/output. Sparse/blank pages are coverage notices, separate from actual per-page parser failures; usable text/pages remain available. Entirely blank decks produce limited-evidence reports, not technical errors. PDF failures do not block usable website evidence, and vice versa. It yields document/page references, not OCR, images or guaranteed table reconstruction. Preserve `pdf-child.mjs` in deployment and enforce container limits.

Private directory/database file permissions are 0700/0600. Raw PDFs are deleted after extraction/cancel/failure, unused uploads after one hour. Parsed checkpoints and encrypted configuration snapshots, inputs, reports and module usage expire with jobs after 24 hours. Some job data is plaintext on private disk; use encrypted volumes for confidentiality at rest beyond key encryption. Cleanup cannot erase external backups/snapshots. See [deployment](deployment.md).

## Validation status

Automated provider and search tests use mock API payloads. PDF tests invoke the real child parser. Non-demo orchestration was also checked through actual HTTP uploads, SQLite persistence and desktop/mobile report export using an explicitly fictional PDF and mock provider: sparse pages, limited evidence, rejected synthesis references and entirely blank PDFs all produced readable saved results. No real paid compatible-provider/Brave call or production HTTPS deployment was performed. The dated acceptance report describes the earlier native-adapter scope, not current capabilities.
